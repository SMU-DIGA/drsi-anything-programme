Models delegate the acting · the delegate carries the knowledge

DRSI-Anything

Delegative Recursive Self-Improvement across General Domains

SMU-DIGA

Design Environments Results Progress Roadmap BibTeX GitHub

Deep RL updates weights. Prompt optimization tunes instructions. We let LLMs rewrite the program itself, keep a version only if it wins on seeds it never saw, and repeat.

TL;DR

An LLM writes a program that solves a task, such as an Atari bot, a robot-arm controller or a desktop agent. A population of LLM improvers (Codex CLI, Claude Code, DeepSeek) then improves that program over many generations, using only feedback from interaction with the environment. Promotion is gated on hidden seeds, and we evaluate on the game, embodied-robotics and computer-use benchmarks the community reports on most often.

Abstract

Deep reinforcement learning improves agents by adjusting weights. Recent evidence suggests that coding agents editing hand-written programs can reach competitive scores on Atari, MuJoCo and VizDoom without any gradient step, and that cross-domain recursive self-improvement loops benefit from frozen evaluation protocols. DRSI-Anything combines the two into a delegative loop: the models that reason and edit (LLMs) do not act in the environment themselves; they delegate the acting to an artifact they write and keep improving, and what is learned is stored in that delegate. Our main delegate is a neuro-symbolic one, readable, testable code and notes that persist across generations, optionally calling smaller models as tools; neuro-symbolic programs are one way to delegate, not the only one. A program, consisting of a policy, its skills and its notes, is improved generation after generation by a heterogeneous population of LLM improvers. Each candidate is re-evaluated in an isolated process and promoted only by a paired test on hidden seeds. We study when such loops keep improving, what transfers across tasks, and how they compare with RL under the same environment-step budget, on games, embodied manipulation (LIBERO, ManiSkill3, SimplerEnv, RoboTwin 2.0) and computer use (OSWorld).

Design

Improve the program, not the weights.

A program is the whole "heuristic system": the policy, its state detectors and skills, and notes holding environment facts, failed ideas and a dated changelog. Each generation runs four steps.

1

Propose

The incumbent is copied into one isolated workspace per improver, with a task brief, per-seed feedback, the full history of earlier attempts, and an evaluator restricted to the train seeds.

2

Re-evaluate

Candidates are re-scored independently. The environment runs in one process and the policy in another, so a policy never sees the reward, the seed or the environment object.

3

Promote

The best candidates face the incumbent on hidden dev seeds under a paired bootstrap gate. Test seeds are used once, at the end.

4

Simplify

The winner is simplified and kept only if its dev score does not drop. This counters the build-up of patches.

Results

Every number is the score of a program written and refined by LLM improvers: no gradient training, no demonstrations. Robustness can be improved too

With sticky actions in the loop, the improvers made the same programs robust. Ms. Pac-Man went from 10,029 to 38,306 on sticky test seeds, two thirds of its no-sticky test score. Montezuma's Revenge went from 3,441 to 113,659 on dev, above its no-sticky score, with real spread across seeds (28,200 to 65,300 for the generation 6 champion), so it is not one memorised game. Under sticky actions dev seeds also stopped tying: all 32 Ms. Pac-Man dev seeds score differently, which makes the paired gate a real test of generalization.

Running now, all with sticky actions and from the generic seed program: the Atari-5 subset (Battle Zone, Double Dunk, Name This Game, Phoenix, Q*bert; Aitchison et al., 2023), whose scores predict performance on the full suite, then the remaining games of Atari-57, four runs at a time. Costs are in Table 10, under Improvers and cost.

Earlier runs without sticky actions

Our first protocol had no sticky actions, so the game was nearly deterministic and many seeds replayed the same game. These runs produced the starting programs above; the tables show what they scored and how much of it survived sticky actions.

Sticky actions: what survives

Every score drops, so part of each no-sticky result came from a deterministic game whose play can be memorised. How much drops follows how the program works. Pong, Breakout and Space Invaders re-plan from the live state at every step and keep half or more. Ms. Pac-Man keeps 18%: it relies on exact timing, such as passing a junction just ahead of a ghost. Montezuma's Revenge keeps 5%: its route is scripted against countdowns and distances, and one mistimed jump costs a life. Under sticky actions four of the five champions still score above the human reference (Breakout about 15×, Space Invaders about 12×, Ms. Pac-Man 1.6×, Pong slightly); Montezuma's Revenge does not. On the same fresh seeds without sticky actions Ms. Pac-Man scored 61,084, above its dev score, so dev itself was not overfitted; the weakness is determinism.

The gate caught overfitting

In generation 3 a candidate scored the maximum on all 8 train seeds but only 714 on dev: it had tuned itself to the few train trajectories. It was rejected. Generation 4 reached 864 on every dev seed and then on every one of the 64 test seeds, which no improver or gate had ever touched.

Recursive improvement, nine generations in a row

Ms. Pac-Man was promoted in every generation so far: 17,207, 19,173, 20,031, 25,663, 29,688, 30,715, 32,295, 34,174, then 50,545 on hidden dev, each version built on the previous one and each winning the paired dev test. The first program decoded the maze, dots and ghosts from RAM and planned over a maze graph. Later generations added escapes at junctions when a ghost is close, detours for fruit, more cautious routing after quick life losses and, in generation 9, a reflex that reverses when a ghost comes head-on on the last life.

A caveat on what dev measures here. Without sticky actions the game is nearly deterministic, so many dev seeds replay the same game. Generation 9 tied its parent exactly on 25 of 32 seeds and won on 7: on those 7 it no longer dies at the same spot and plays to the 27,000-step limit (37,491 → about 112,330). The gain is real, but it fixes one failure that recurs across seeds rather than showing broad generalization; Table 4 shows the cost under sticky actions.

Montezuma's Revenge without exploration bonuses

The promoted program follows an explicit room-by-room route over RAM state (room, position, inventory, enemy positions, and a laser countdown it discovered). It times jumps on the skull's live position and laser crossings on the countdown, collects keys, treasures and a sword, and opens four doors. Where a respawn keeps the inventory, it loses a life on purpose as a shortcut back. Generation 6 extended the route through level 2, keeping both keys for the exit doors and collecting its prizes, and into level 3 (53,700 on every dev seed). Caveat: without sticky actions, different seeds mostly shift start-up timing, so dev mainly tests robustness to timing; under sticky actions it keeps only 5% (Table 4); the sticky run brought it back (Table 2).

Space Invaders by aiming, not by luck

The program located the invader grid, its speed and descent, both enemy bullets and the shields in RAM, and fitted the missile's flight time from about 1,700 kills. It fires with a lead computed from the grid's motion and steps out of the path of falling bullets.

For scale: the readable Leduc policy (test 0.106) sits between 30 and 100 iterations of vanilla CFR run on each test variant, which reaches 0.005 after 1,000 iterations. It generalizes across variants without solving any of them, but it is still far from an equilibrium.

HUNL: the champion beats the rule bots (call station, maniac, equity bot) and earlier champions by 29,090 mbb/hand on 64 test seeds, but those opponents are easy to exploit. Against DecisionHoldem, a strong published agent, the same program loses about 4.6 big blinds per hand (± 1.9, standard error over 8 seeds of 50 hands each), so beating weak opponents did not make it strong. The starting program (always call) scores −1.7 big blinds per hand (± 1.4) on the same 8 seeds, so the champion is, if anything, not better than its starting point against DecisionHoldem; with 8 seeds the gap is within noise. DecisionHoldem's search makes every hand take seconds, so this is a small sample; a loop that trains against DecisionHoldem directly is being set up.

A run we threw away

The first HUNL run reported +62,790 mbb/hand, which was too good to be true. Its program had found a hole in our harness: the mirrored hand of each duplicate pair was replayed right away in the same process, so it could remember the board and its own earlier cards, which were now its opponent's. Each seat is now played by a separate, fresh process; every deal is seen once per process; and temp files, sockets, subprocesses and native code are rejected. The run was restarted from scratch.

How to read these numbers

No demonstrations and no learned weights: every policy is readable code. State mode is easier than the VLA setting and is not comparable to it. Vision mode is the closest match, but it uses depth and camera calibration, which the VLA models do not. Programs contain routines per task family and generalize across unseen initial scenes, which is what LIBERO's protocol tests.

What the programs found by probing

The vision program measured that its agent-view estimate of a bowl's centre is biased by about 4 cm, so it re-centres with the wrist camera before grasping. The LIBERO-10 program worked out each goal condition (e.g. the stove counts as on once its knob turns past about 0.45 rad) and found initial scenes where objects fly off the table on the first step, which no policy can solve.

LIBERO-Spatial vision finished its 10 generations at 95.0% on dev. In the last generation two candidates reached 96.3%, but one extra win was not enough for the paired gate. On the 400 test episodes it scored 95.3%, in line with dev. Running next: the vision setting on LIBERO-10, LIBERO-Object and LIBERO-Goal, each starting from the LIBERO-Spatial vision champion, so that all four suites compare with OpenVLA-OFT. ManiSkill3 is queued.

A large train–dev gap

Both champions solve most train tasks (65% and 78%) but few dev tasks. They are skill libraries: regular expressions map an instruction to a handler that scripts LibreOffice through its UNO interface or runs shell and settings commands. A handler written for a train task rarely covers a dev task, which usually needs a different skill. The better run (5 / 24) probes the desktop first and has 28 spreadsheet and about 20 desktop handlers.

The model was available but not used

The 5 / 24 champion never calls the small model; only unpromoted candidates did. So the difference between the two runs is two independent searches over pure-code programs, not evidence that the model helps. The next runs cover eight applications (Calc, Writer, Impress, OS, VS Code, GIMP, VLC, Thunderbird; 222 tasks split by application into 70 / 76 / 76) and tell the improvers where the model can help, so the comparison becomes a real ablation.

The program decides every action in code, including running code inside the desktop and reading its output. The model never writes text or actions; it returns a probability per option and acts as a smart if-statement inside the program (in the style of TypeSafe's Jev). In both settings the program may learn a memory from its own train episodes, frozen during dev and test.

Most environment steps are spent by the improvers' own trial runs (64–90% for Atari), not by the gates. An Atari run uses 15–100 M steps (60–400 M frames): the same order as the standard deep-RL budget of 200 M frames, and far above sample-efficient settings such as Atari 100k (400 K frames). Sample efficiency is a weakness of this loop. In money a run costs tens of dollars of agent time.
