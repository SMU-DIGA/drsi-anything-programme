DRSI-Anything

Delegative Recursive Self-Improvement across General Domains

SMU-DIGA

Design Environments Results BibTeX GitHub

LLMs rewrite the program, not the weights. A version survives only if it wins on seeds no one has seen.

TL;DR

Coding agents write a program for a task and improve it over many generations, using only feedback from the environment. A new version replaces the old one only if it wins on hidden seeds. One loop, five domains.

Design

1

Propose

Each improver edits its own copy, seeing train seeds only.

2

Re-evaluate

Every candidate is re-scored in isolation; self-reported scores are ignored.

3

Promote

Only a paired win on hidden dev seeds replaces the incumbent.

4

Test once

Test seeds are used after the run, never to choose a version.

RGB frames only, sticky actions (p = 0.25), from a generic seed program. Dashed lines: human, Rainbow and Muesli.

{% include curves-atari5.html %}

One program for all five games, from the screen alone

The five champions merged into one program that is not told the game: no game id, no info, the full 18-action set. It recognises the game from the first frame (21 × 16 colour cells, nearest reference screen) and runs that game's program.

ScienceWorld: one program for 30 experiments

Boil, melt, wire circuits, test conductivity, grow plants, cross them for Mendelian traits: one program reads the text observation and answers with one command per step. It calls no model and never sees the gold actions; test variations use substances, objects and rooms that train never shows.

Found by probing

The vision program measured a 4 cm bias in its bowl estimate and re-centres with the wrist camera before grasping. The LIBERO-10 program worked out each goal condition (the stove counts as on past 0.45 rad).

Next: LIBERO-Object and LIBERO-Goal from vision, then ManiSkill3.

{% include curves-computer.html %}

A large train–dev gap

Both champions are libraries of handlers matched to instructions; a handler written for a train task rarely covers an unseen one. The better champion never calls the model, so the two runs differ by search, not by the model.

Next: all ten applications (360 tasks) with models for perception only (text and UI-element detection) and every decision in code.

ARC-AGI-1, 2 and 3: one program

Static puzzles (ARC-AGI-1, 2; pass@2, exact match) and interactive games (ARC-AGI-3, official engine offline, level-weighted score), solved by one program that is never told the puzzle, the game or whether an answer was right.

ARC-AGI-1 rises, ARC-AGI-3 starts, ARC-AGI-2 not yet

Games: in generation 7 an improver found that most games draw a step counter that changes every action, so no frame ever repeated; separating it let the program revisit states, and it now clears a first level in 3 of 8 dev games. Puzzles: train gains often stay on train (one candidate solved 7 more ARC-AGI-1 train puzzles and no more dev puzzles).

Paused after generation 7; $243 of improver sessions. Next: the program infers each rule at run time (observe, hypothesise, test, revise), measured by leave-one-out on the demonstration pairs; train adds ConceptARC, MINI-ARC and RE-ARC.
